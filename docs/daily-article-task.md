# 毎日の記事自動作成の手順（自動実行用）

この手順は、毎日深夜2時（日本時間）に起動する自動作業で使う。人の確認なしで公開まで行うため、品質と正確さを最優先にする。1回の実行で作る記事は1本だけ。

## 1. 準備

1. リポジトリ uk-support1/fukushi-website-comparison の main を最新にし、`daily/YYYYMMDD`（日本時間の今日）ブランチを main から作る。
2. `docs/blog-writing-guide.md`（書式・編集方針・予約投稿・カバー画像）を読む。
3. `docs/blog-topic-queue.md` の最初の未着手（`- [ ]`）テーマを選ぶ。
4. `content/blog/` の既存記事と、`docs/partner-blog-topics.md`（福祉ITパートナーのブログ一覧）を確認し、テーマ・切り口・タイトルが重なる場合はそのテーマを「- [x]（重複のため見送り）」にして次のテーマにする。
   - 可能なら https://fukushi-it-partner.com/sitemap.xml から一覧を取り直して `docs/partner-blog-topics.md` を更新する。

## 2. 調査

- WebSearch で、厚生労働省・こども家庭庁・警察庁・IPA・個人情報保護委員会・WAM NET・都道府県などの公的情報を優先して確認する。
- 数字・制度の要件・施行時期など、確認できなかったことは書かない（または「自治体に確認」と明記する）。
- 出典に載せるURLは、実際に開けること（HTTP 200）を確認したものだけにする。開けないものは載せない。

## 3. 執筆（content/blog/<スラッグ>.md）

- 書式は既存記事にならう。必須：title、description、category、date（日本時間の今日）、cover（`{"catch": "短い見出し／改行位置", "sub": "補足"}`）、lead、summary、related（既存記事のスラッグ3つ）、faq（3問）、sources。
- 本文は3,000〜5,000字程度。見出し（##）4〜7個、表やチェックリスト、囲みボックスを使って読みやすく。
- 対象読者は福祉事業所の運営者・担当者。中立な立場で書き、特定の制作会社（福祉ITパートナーを含む）を勧めない。比較記事や既存記事へのリンクは自然な範囲で入れる。
- 福祉ITパートナーのブログ記事の構成・文章を参考にしたり流用したりしない。
- 誇張・断定（「必ず」「No.1」など）や、根拠のない数字は使わない。

## 4. 生成と確認

1. `node scripts/make-blog-covers.cjs`（新しい記事のカバー画像を生成）
2. `node scripts/build-blog.cjs`
3. `node scripts/check-links.cjs .`（bad 0 であること）
4. 生成されたカバー画像を目で確認し、見出しが不自然に改行されていれば cover.catch の「／」位置を直して `--force` で作り直す。
5. `docs/blog-topic-queue.md` の該当テーマを `- [x]` にし、末尾に「（YYYY-MM-DD 公開: <スラッグ>）」を書く。

## 5. 公開

1. コミットメッセージは日本語で「お役立ち記事を追加：<タイトル>」。
2. `daily/YYYYMMDD` を push し、main へのプルリクエストを作成（本文に記事タイトル、出典、確認結果を日本語で書く）。
3. プルリクエストをマージする（運営者から「確認なしでマージしてよい」と許可を得ている）。
4. 数分後に https://fukushi-hp-hikaku.com/blog/<スラッグ>/ が表示されることを確認する。GitHub Pages の公開処理がタイムアウトで失敗していたら、Actions の該当実行を再実行する。

## うまくいかないとき

- 調査で十分な根拠が得られない、ビルドやリンクチェックが通らない場合は、無理に公開しない。プルリクエストを下書きのまま残し、理由を本文に書いて終了する。
- 既存の記事・比較ページ・デザインは変更しない（この作業は記事を1本追加するだけ）。
