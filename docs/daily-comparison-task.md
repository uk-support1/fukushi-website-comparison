# 業種別比較記事の自動作成手順（毎日1本）

毎日朝4時ごろ（日本時間）に自動で起動し、`docs/comparison-queue.md` の次の業種について、ホームページ制作会社の比較記事を1本作成・公開する。人の確認なしで公開するため、**正確さと中立性を最優先**にする。

## 0. 大前提（必ず守る）

- 料金・プラン・対応内容は、**各社の公式サイトを実際に開いて確認したものだけ**を書く。確認できない項目は「要確認」「公式サイトに記載なし」と書き、推測で埋めない。
- 確認日（情報時点）を記事に明記する。税込・税別を必ず書き分け、比較表は税込相当に統一する（税別×1.1、元の表記も併記）。
- 掲載は**3社以上**。3社に満たない場合は公開せず、キューに「保留」と理由を書いて終了する。
- 当サイトは掲載企業の一社である福祉ITパートナーの関連会社が運営している。そのため**福祉ITパートナーを特別扱いしない**。掲載順は客観的な基準（1年間の費用の安い順）を基本にするが、**福祉ITパートナーは先頭にせず、必ず2番目に掲載する**（運営者の指示）。この並べ方も記事内に書く。「おすすめNo.1」などの根拠のない順位づけはしない。各社に良い点と注意点の両方を書く。
- 他の業種の比較記事と**ほぼ同じ内容のページ（言い換えただけ・業種名を差し替えただけ）にしない**。Googleの「誘導ページ（doorway）」と判断されるおそれがある。業種固有の内容（下記4）を厚くする。
- 福祉ITパートナーのブログ記事の文章・構成を流用しない。

## 料金の見せ方（運営者の指示。必ず守る）

- 料金で強調するのは「**1年間の費用の目安**（初期費用＋月額×12か月・税込相当）」だけ。表でも各社の紹介欄でも、これを大きく表示し、一番安い会社だけ強調（ハイライト）する。
- **初期費用・月額費用は、たとえ0円でも強調しない。** 表に「初期費用」「月額費用」の独立した行を作らず、1年間の費用と同じ枠の中に小さい文字で内訳として添える（例：`初期0円＋月額9,790円×12か月`）。
- 掲載順（表の列、各社の紹介の並び）は、1年間の費用の安い順を基本にする。ただし福祉ITパートナーが先頭になる場合は、先頭にせず2番目に掲載する（2番目の会社と入れ替える）。記事の導入文と末尾の開示欄に「1年間の費用の安い順を基本としていますが、運営の関連会社である福祉ITパートナーは、先頭にせず2番目に掲載しています」と書く。
- 「初期費用をかけずに始めたい」のように、初期費用を売りにする見出し・おすすめ文は使わない。「1年間の費用を抑えたい」など1年間の費用を基準にする。
- 月額が確認できない会社は「297,000円～」のように確認できた範囲で書き、内訳に「月額は公式サイトで確認できず」と明記する。
- 公開後の更新を自社で行う前提の会社（月額契約なし）は、1年間の費用に更新代行の費用が含まれないことを注記する。
- 実装の例は `comparisons/shuro-iko-comparison.html`（クラス `cw-matrix-price`／`cw-price-total`／`cw-price-break`、`cw-spec-grid--price`）を参照する。

## 評価の見せ方（◎○△）（運営者の指示。必ず守る）

比較表（章「1．比較表」）は、福祉事業所向けの比較記事（`comparisons/welfare-comparison.html`）と同じ項目・形式にする。

- 行は次の順にする：**1年間の費用の目安／福祉への理解／デザインの自由度／相談しやすさ／公開後の更新・サポート／納期の目安／こんな方に**。業種に関する公式サイトの記載、ページ構成、契約期間などは、章「4．費用を詳しく比較」の表に入れる。
- 費用以外の5行は、各社を **◎・○・△** で評価し、セルの中に根拠を一文（小さい文字・`cw-eval-note`）で添える。◎のセルだけ強調（`cw-matrix-best`）する。実装は `comparisons/shuro-iko-comparison.html` を参照。
- 基準：◎＝公式サイトの記載で特に充実していると確認できる／○＝対応を確認できる／△＝限定的、または記載を確認できない。確認できなかったことは「公式サイトに記載なし」と書き、推測で◎○にしない。
  - 福祉への理解：◎＝福祉に特化、福祉事業の運営経験・専門資格・福祉業界出身の担当者が明記されている／○＝福祉施設向けの専用ページや制作実績がある／△＝記載を確認できない。
  - デザインの自由度：◎＝オリジナルデザインに対応／○＝カスタム可能なテンプレート・個別デザインの提案／△＝テンプレート中心・基本デザイン。
  - 相談しやすさ：◎＝無料相談があり、福祉の現場経験者・福祉特化の担当者が対応／○＝相談窓口がある／△＝記載を確認できない。
  - 公開後の更新・サポート：◎＝月額内の更新代行など、依頼できる体制が手厚い／○＝自社で更新できる、または運用サポートがある／△＝範囲が不明・記載なし。
  - 納期の目安：◎＝最短1週間以内の明記／○＝1か月程度まで／△＝記載なし・それ以上。
- 同じ会社は、記事が違っても同じ基準で評価する（根拠の一文に、その業種の制作実績の有無を添えるのは可）。
- 表の下に、凡例（`cw-legend`）と「◎○△は公式サイトの記載にもとづく編集部の評価／評価は他社と同じ基準／福祉ITパートナーの関連会社が運営している」旨の注記を必ず入れる。

## 1. 準備

1. main を最新にし、`compare/YYYYMMDD` ブランチを作る。
2. `docs/comparison-queue.md` の最初の未着手の業種を選ぶ。
3. 既存の比較記事（`comparisons/*.html`）と `assets/data/comparisons.json`、`assets/js/company-data.js`、`docs/directory-maintenance.md` を読み、構成と情報の扱い方を把握する。

## 2. 掲載会社の選定と確認

1. WebSearch で「<業種> ホームページ制作」などを検索し、その業種または障害福祉事業所向けの制作サービスを候補に挙げる（既存比較記事の掲載会社も候補）。
2. 各社の公式サイトを curl などで開き、次を確認・記録する（出典URLと確認日）。
   - プラン名・初期費用・月額費用（税込/税別）・最低契約期間
   - ページ数、文章作成・写真の支援、スマホ対応、問い合わせフォーム、Googleマップ、SEO
   - 自社で更新できるか、更新代行の有無と料金、公開後の保守
   - その業種（または障害福祉）の制作実績の有無（公式サイトに記載があるもののみ）
3. 公式サイトが開けない会社、料金が確認できない会社は掲載しない（または「料金は要問い合わせ」と明記したうえで掲載）。

## 3. ページの作成（comparisons/<slug>-comparison.html）

- `comparisons/group-home-comparison.html` の構成・CSS・ヘッダー・フッター（運営者の関係表示を含む）・GA4タグを踏襲して新しいHTMLを作る。章立ての例：
  1. 比較表（全社）
  2. 目的別の選び方
  3. 各社の料金・特徴（良い点／注意点）
  4. 費用・サポートの詳しい比較（1年目の総額の試算を含む）
  5. <業種>のホームページの選び方・載せるべき内容（業種固有）
  6. まとめ
  7. よくある質問（業種固有、3〜5問）
  8. 本記事の比較について（情報時点・出典・運営者との関係）
- title・description・canonical・OGP（og:image は `assets/images/comparisons/<slug>/card.jpg`）・パンくずと構造化データ（BreadcrumbList、WebPage）を設定する。
- 章のバナー画像は既存の `assets/images/comparisons/welfare/` のものを使ってよい（alt は内容に合わせる）。
- 関連するお役立ち記事（制度解説など）へのリンクを本文に入れる。

## 4. 業種固有の内容（重複を避けるため必須）

その業種の利用者・家族・相談支援専門員・求職者が何を知りたいか、制度上何を公表する必要があるかを、その業種の事情に合わせて書く。例：
- 放課後等デイサービス：支援プログラム・自己評価/保護者評価の公表、送迎範囲、学校からの迎え、空き曜日、写真掲載の同意
- 就労移行支援：就職実績・定着率の見せ方、訓練内容、企業向けページ
- 生活介護：活動内容、入浴・医療的ケア、送迎、サービス提供時間
- 相談支援：相談の流れ、対応地域、空き状況、関係機関向け情報
制度の記述は公的機関の情報で確認し、確認できないことは書かない。

## 5. 登録と生成

1. `assets/data/comparisons.json` に新しい比較記事を追加する（slug、file、title、cardTitle、desc、companies、infoDate、cover）。
2. `node scripts/make-blog-covers.cjs`（カード画像 `assets/images/comparisons/<slug>/card.jpg` と `card-sm.jpg` を生成）
3. `node scripts/build-blog.cjs`（トップページのカード・記事内の導線・サイトマップを更新）
4. `node scripts/check-links.cjs .`（bad 0 であること）
5. Playwright でパソコン幅とスマホ幅（390px）を表示し、横スクロールがないこと、表が崩れていないことを確認する。
6. `docs/comparison-queue.md` を更新する（`- [x]` と公開日・ファイル名）。

## 6. 公開

1. コミットメッセージは日本語で「比較記事を追加：<業種>向けホームページ制作会社比較」。
2. push してプルリクエストを作成し（本文に掲載会社・確認日・出典URL・確認結果を日本語で書く）、マージする（運営者から確認なしでのマージ・公開の許可あり）。
3. 本番URLが表示されることを確認する。GitHub Pages の公開処理がタイムアウトで失敗していたら、該当の実行を再実行する。

### プルリクエスト用のツールがない場合

GitHub のプルリクエスト作成・マージのツール（mcp__github__*）が使えない環境では、次の方法で公開する（運営者の許可あり）。

1. `compare/YYYYMMDD` ブランチを push して記録を残す（失敗しても続行してよい）。
2. `git fetch origin main && git checkout main && git reset --hard origin/main` で最新の main にする。
3. `git merge --no-ff compare/YYYYMMDD -m "<コミットメッセージと同じ内容>"` でマージする。
4. `node scripts/build-blog.cjs` と `node scripts/check-links.cjs .` をもう一度実行し、生成物に差分があればコミットする。
5. `git push origin main` で公開する。push が拒否された場合は無理に回避せず、状況を報告して終了する。

## うまくいかないとき

- 3社以上の確認ができない、根拠が不十分、ビルドやリンクチェックが通らない場合は公開しない。キューに保留理由を書き、下書きのプルリクエストに状況を残して終了する。
- 既存の比較記事・お役立ち記事・デザインは変更しない（新しい比較記事の追加と、それに伴う一覧・サイトマップの自動更新だけを行う）。
